# 系统总览

## 目标

本工具用于从启用了远程调试的 Chrome 实例中采集网络请求、响应以及 WebSocket 消息，并将结果落地为结构化文件。

## 能力范围

当前覆盖三类能力：

- 通用抓包：适用于任意网站
- OPS 菜单抓包：在通用抓包基础上增加菜单识别与按菜单归档
- 精简导出：将原始 NDJSON 转换为便于分析的精简 JSON

## 分层模型

- PowerShell 包装层：负责运行入口、Chrome 启动、Tab 选择、参数整理
- Node 实现层：负责 CDP 连接、事件订阅、数据组装、过滤、落地输出

## 目录约定

- `scripts/powershell`：可执行包装脚本与 PowerShell 辅助函数
- `src/capture/cli`：Node CLI 入口
- `src/capture/lib`：共享实现
- `docs/functional`：功能、边界、使用方式
- `docs/validation`：验证步骤与验证结果

## 职责边界

通用抓包负责：

- 连接 CDP
- 选择目标 Tab
- 采集请求、响应与 WebSocket 事件
- 根据规则过滤
- 按接口路径落地 HTTP 原始数据
- 按站点、页面、连接落地 WebSocket 原始数据

OPS 菜单抓包只额外负责：

- 识别当前页面菜单
- 按菜单目录归档抓包结果

精简导出负责：

- 递归读取原始文件
- 保留接口、方法、请求参数、响应体等核心字段
- 输出参数类型与响应类型

## 扩展规则

- 新的网站定制能力应以独立适配层接入，不得侵入通用链路
- 包装层保持轻量，不在 PowerShell 中堆积业务逻辑
- 新增功能时，先补功能说明，再补验证文档
- 遇到多 Tab、多 Profile、多站点等场景，优先提供显式选择能力，而不是隐藏推断
